# RelationScope V3 — Continuous Learning & Document Intelligence

RelationScope V3 completes the project roadmap by moving from entity-pair inference to a governed relation-intelligence platform.

V1 established a calibrated open-set relation classifier and production deployment. V2 added explainability, privacy-preserving observability, human feedback, durable batch jobs and model lifecycle primitives. V3 adds automatic document analysis, active learning, drift detection, versioned retraining data, promotion gates, champion/challenger canaries and rollback.

The frozen V1 evaluation protocol remains the reference benchmark. V3 does not reuse the final unseen-relation test set for threshold tuning or active-learning selection.

## 1. Raw document to knowledge graph

V3 no longer requires callers to supply HEAD and TAIL spans for document analysis.

```text
PDF / TXT / raw text
        |
        v
Automatic entity extraction
        |
        v
Sentence segmentation
        |
        v
Candidate entity-pair generation
        |
        v
ModernBERT open-set relation extraction
        |
        +--> KNOWN relation
        |
        +--> UNKNOWN relation
        |
        v
Canonical entity graph
```

Endpoints:

```text
POST /v3/documents:analyze
POST /v3/documents:upload
```

The upload endpoint accepts UTF-8 text or PDFs up to 10 MiB. PDF text is extracted with `pypdf`.

### Entity extraction modes

`RELATIONSCOPE_NER_MODEL` controls entity discovery:

- empty: deterministic, zero-download title-case/acronym heuristic;
- non-empty: Hugging Face/local token-classification model with aggregated spans.

The heuristic is a safe local fallback, not a claim of state-of-the-art NER. A reviewed, versioned NER model should be configured before treating automatic entity discovery as a production-quality extraction stage.

## 2. Document candidate generation

Entities are assigned stable canonical IDs using normalized text + entity type.

Relation candidates are currently generated for **ordered entity pairs within the same sentence**. This avoids pretending that the V1 sentence-level relation model has been validated for arbitrary cross-sentence relation classification.

The API caps candidate generation with `max_candidate_pairs` so long documents cannot create unbounded quadratic inference work.

Accepted relations become graph edges. Unknown edges can optionally be included for inspection.

## 3. Active learning

V3 scores each open-set prediction using:

```text
score =
    0.55 * uncertainty
  + 0.35 * threshold proximity
  + 0.10 * UNKNOWN bonus
```

Default queue threshold:

```text
0.55
```

The policy is exposed at:

```text
GET /v3/active-learning/policy
```

Raw sentence/entity data enters the review queue **only** when the caller explicitly sets:

```text
consent_to_store_review_data=true
```

Without that consent, V3 may count an example as an interesting review candidate but does not persist its raw text.

The private review API is under:

```text
GET  /v3/internal/review-queue
POST /v3/internal/review-queue/{review_id}:review
```

The public Next.js proxy blocks all `/v3/internal/*` routes.

## 4. Versioned training datasets

Reviewed V2 feedback and reviewed V3 active-learning items can be converted into an immutable local snapshot:

```bash
uv run python scripts/create_dataset_snapshot.py \
  --dataset-version review-2026-09-24 \
  --ops-bucket YOUR_OPS_BUCKET
```

Output:

```text
artifacts/datasets/<dataset-version>/
├── examples.jsonl
└── manifest.json
```

The manifest contains:

- dataset version;
- creation timestamp;
- record count;
- SHA-256 over the exact JSONL bytes;
- counts by source;
- counts by relation.

Records are deduplicated by text, spans and reviewed target relation.

Only examples with raw-data consent can enter the snapshot.

## 5. Reviewed-data retraining

The existing open-set training script now accepts:

```text
--review-snapshot <examples.jsonl>
--candidate-model-version <version>
```

Only reviewed examples mapped to an **existing known relation ID** are added to supervised training. Reviewed `UNKNOWN_RELATION` examples are not silently turned into classifier labels.

The frozen validation/calibration/final test protocol remains unchanged.

A one-command offline orchestration is available:

```bash
uv run python scripts/run_v3_retraining_pipeline.py \
  --review-snapshot artifacts/datasets/review-2026-09-24/examples.jsonl \
  --candidate-model-version modernbert-open-set-v2.0 \
  --output-dir artifacts/v3_candidate
```

The command:

1. trains a challenger using the reviewed known examples;
2. evaluates on the frozen protocol;
3. writes `candidate_report.json`;
4. evaluates champion/challenger promotion gates;
5. writes `promotion_gate.json`;
6. exits non-zero if the candidate fails.

It deliberately does **not** promote a model automatically.

## 6. Promotion gates

Default V3 gates compare the challenger against the champion on the same protocol:

- protocol name must match exactly;
- known Macro-F1 may regress by at most 0.005;
- unknown-F1 may regress by at most 0.01;
- OOD AUROC may regress by at most 0.01;
- unknown rejection may regress by at most 0.02;
- accepted-known accuracy may regress by at most 0.005;
- warm Cloud Run CPU median, when present, must remain within 1.25x champion.

Run independently:

```bash
uv run python scripts/evaluate_promotion_gate.py \
  --challenger artifacts/v3_candidate/candidate_report.json \
  --output artifacts/v3_candidate/promotion_gate.json
```

These are project governance thresholds, not universal scientific constants. They are explicit and version-controlled so a change to the release policy is reviewable.

## 7. Drift detection

V3 extends telemetry with predicted relation ID/name and deployment variant.

`GET /v3/drift` compares the newest telemetry window with the immediately preceding window.

Signals:

- UNKNOWN-rate increase;
- mean-confidence drop;
- relative mean-input-length change;
- Jensen-Shannon divergence of predicted relation IDs.

Default alert thresholds:

- UNKNOWN-rate delta > 0.15;
- mean confidence drop > 0.10;
- absolute relative mean text-length change > 0.30;
- relation JS divergence > 0.20.

Status:

```text
insufficient_data
healthy
watch
alert
```

At least 20 events per comparison window are required by default.

This detects operational distribution change; it does not prove semantic dataset drift or model degradation by itself.

## 8. Champion / challenger canary

Terraform can optionally provision a second private Cloud Run API.

```text
                    +--> champion API
public Next.js -----|
                    +--> challenger API
```

Configuration:

```hcl
enable_challenger       = true
challenger_model_prefix = "models/releases/modernbert-open-set-v2.0"
canary_percent          = 5
```

The Next.js server proxy uses a sticky 30-day canary key and deterministic bucketing. Eligible inference requests are routed to the challenger according to `canary_percent`.

Eligible routes:

- `POST /v2/relations:predict-open-set`;
- `POST /v2/relations:explain`;
- `POST /v3/documents:analyze`;
- `POST /v3/documents:upload`.

The response includes:

```text
x-relationscope-variant: champion|challenger
```

Both APIs remain private. The web service account receives `roles/run.invoker` on each service.

The challenger uses its immutable model release prefix rather than `models/current`.

## 9. Rollback

Model rollback is explicit and audited:

```bash
uv run python scripts/rollback_model_release.py \
  --bucket YOUR_MODEL_BUCKET \
  --model-version modernbert-open-set-v1.1
```

If `--model-version` is omitted, the script selects the previous distinct model from promotion history.

Rollback:

1. verifies that the immutable registered release exists;
2. replaces the `models/current` alias;
3. writes an audit event under `models/rollbacks/`.

A Cloud Run revision still needs to reload/restart before a process already holding the old model in memory will use the new alias. Rollback of the GCS alias and rollback of running traffic are therefore treated as related but separate operational actions.

## 10. Safe public learning dashboard

The public frontend shows only aggregate continuous-learning state:

- pending-review count;
- reviewed count;
- dismissed count;
- drift status;
- champion model ID;
- canary percentage;
- registered challenger version.

It never exposes review-queue raw text through the public proxy.

## 11. Privacy boundaries

V3 preserves the V2 privacy model:

- request middleware does not log bodies;
- prediction telemetry stores hashes/lengths, not raw text;
- V2 feedback raw text is opt-in;
- V3 review-queue raw text is opt-in;
- internal review/admin routes are blocked by the public web proxy;
- training snapshots are built only from consented/reviewed examples.
